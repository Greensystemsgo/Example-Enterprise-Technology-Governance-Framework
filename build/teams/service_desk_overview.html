Service Desk Overview

1. Mission

Provide a disciplined, customer-facing intake function that routes technology needs through the governance gates with complete documentation and transparent communication. These recommendations reflect best practices aligned with the Mayor's Executive Directive on cybersecurity and are not formal policy.

2. Core Outcomes

  • Centralized Intake: Operate the organization's request solution so every technology action starts with a complete, auditable record.
  • Workstation Stewardship: Manage the end-user compute lifecycle (deployment, refresh, retirement) unless the organization assigns those duties elsewhere; participate in server workflows when organizational policy requires.
  • Intake Quality: Ensure every request includes mandatory data, ownership acknowledgement, and business justification before advancing.
  • Communication: Keep requestors informed of gate progress, required actions, and status changes.
  • Knowledge Enablement: Maintain user-facing FAQs, request catalog entries, and self-service guidance aligned with approved standards.
  • Operational Insight: Produce metrics on request volume, aging, gate rejections, and ad-hoc attempts routed back into the centralized process.

3. Engagement in the Request Lifecycle

  • Gate 0: Validate intake forms in the centralized system, assign tracking IDs, and capture funding details and ownership commitments.
  • Gate 1: Coordinate with core teams to confirm impact assessments and return incomplete submissions or ad-hoc requests to the centralized process.
  • Gate 4: Publish implementation communications, outage notices, and user readiness instructions.
  • Gate 5: Confirm handoffs are acknowledged, audit evidence is stored, and update request records with closure notes.

4. Collaboration Touchpoints

  • Infrastructure: Share workload forecasts and provide standardized intake packages for common build patterns.
  • Active Directory Team: Align on account provisioning requirements, naming conventions, and approval workflows that must traverse the centralized request path.
  • Network Team: Communicate connectivity prerequisites, cutover windows, and user impact notices.
  • Security Team: Relay risk mitigation requirements, logging mandates, and exception outcomes back to requestors.

5. Key Checklists and Artifacts

  • Service Desk Intake Completeness Checklist: ensures mandatory fields and supporting documents are present.
  • Service Desk Communication Plan: guides implementation and post-implementation updates.
  • Service Catalog Entry Template: captures scope, fulfillment steps, and eligibility criteria.
  • Service Desk Metrics Dashboard: outlines request volume, cycle times, gate rejection reasons, and compliance with centralized intake.

6. Continuous Improvement

  • Review escalations and rejected requests monthly to refine intake guidance and templates.
  • Provide refresher training for requestors on documentation expectations, logging requirements, and gate sequencing.
  • Capture user satisfaction feedback and share insights with the Governance Council.
  • Update self-service resources whenever standards, templates, or gate requirements change.
